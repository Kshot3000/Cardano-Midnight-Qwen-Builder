🤝 Agent Escrow Protocol

AI agents need budgets, not vibes. Release on-chain escrow only after a signed milestone, usage proof, or human approval. Low-cost Cardano settlement makes that practical for agent marketplaces. The killer feature isn't autonomy — it's accountable execution.

💰 Escrow

The client deposits the full budget in ADA (lovelace). Funds stay locked until each milestone is released or the remainder is refunded.

Cardanolovelace

📜 Proofs

The agent submits a proof hash per milestone — a SHA-256 over the artifact, a ZK witness commitment, or a signed receipt. On Midnight, the proof can be a ZK circuit that selectively discloses *only* "milestone done".

MidnightZK

🛡 Separation of duties

The agent can submit proofs but never approve. Only registered approvers (always including the client) release or reject milestones. Self-approval is a protocol error by construction.

access control

🧾 Audit trail

Every transition appends an immutable event: (seq, at, type, actor, stateBefore, stateAfter, data) with a monotonic sequence — the verifiable-workload receipt.

accountability

⚖️ Disputes

Disputes freeze all releases. Only the client resolves: full refund of the remaining balance, or resume the engagement. Late approvals are flagged, not blocked — a hook for penalty logic.

⚙️ The state machine

created ──fund──▶ funded ──start──▶ in_progress ──settle──▶ settled
                    │    │               │  │
                    │    └───cancel──────┘  └──dispute──▶ disputed
                    │                             │
                    └────────────cancel───────────┘
                                          ┌──────┴──────┐
                                      refund           resume
                                          │             │
                                       refunded    in_progress

Per milestone: pending → proof_submitted → released | rejected. settle is allowed once every milestone is released or rejected; it refunds the remainder. Full rules, proof model, and the Cardano on-chain mapping live in SPEC.md.

▶ Demo output (JavaScript)

=== Agent Escrow Protocol — demo walkthrough ===

1) Alice creates an escrow for a builder agent: 3 milestones, 10 ADA budget.
2) She funds it — 10 ADA (10,000,000 lovelace).
  [1] funded               actor=alice-addr     created -> funded  {"amount":10000000}
3) Work starts.
  [2] started              actor=alice-addr     funded -> in_progress  {"milestoneTotal":10000000}
4) Milestone 1: the agent submits its proof hash.
  [3] proof_submitted      actor=builder-agent  in_progress -> in_progress  {"milestone":"m1","proofHash":"0x9f2c41ab"}
5) The auditor verifies the repo scaffold and releases m1 (1 ADA).
  [4] milestone_released   actor=charlie-auditor in_progress -> in_progress  {"milestone":"m1","amount":1000000,"late":false}
...
9) All milestones decided -> settle refunds the unspent remainder.
  [9] settled             actor=alice-addr     in_progress -> settled  {"refund":4000000}

Milestones: {"m1":"released","m2":"rejected","m3":"released"}
Final state: settled | released: 6 ADA
Invariants OK: released + refunded == funded, audit seqs monotonic.

=== Security check: the agent tries to approve its own work ===
Blocked as designed: SELF_APPROVAL — the agent cannot approve its own work
