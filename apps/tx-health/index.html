🧠 About this dashboard

Data: public NightForge explorer API (mainnet.nightforge.jp) — /api/analytics/tx-health (lifetime applied vs partial-success, local index, recent partials) and /api/governance/d-parameter (on-chain decentralization parameter history). The settlement health score is a transparent rubric (clean settlement, low partial rate, ledger adds up, self-consistent), computed in txhealth.js and covered by 30 unit tests. The partial rate shown is recomputed from raw counts and cross-checked against the indexer-reported value; the recent-partial register is de-duplicated, because the indexer is known to emit the same tx up to three times. If the indexer stops exposing a field, this page shows – rather than inventing a number.

"Partial-success" means the extrinsic was included and its state effects applied, but at least one inner call returned an error — common with multi-call governance and bridge operations. It is a real settlement-quality signal, not a transaction failure: the fees were paid and the partial effects are on the ledger. The D-parameter governs which validator candidates may be elected: the permissioned set is fixed by governance, the registered set is open. This is an informational tool — verify figures against the official explorer before relying on them.
