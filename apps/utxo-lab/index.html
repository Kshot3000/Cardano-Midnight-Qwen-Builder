🧪 UTxO Lab

Cardano doesn't have a balance — it has UTxOs. Every transaction spends whole inputs and re-emits what's left as change. This lab runs the real planning math offline: coin selection, the 44 + 15.3·bytes fee, the minimum-output-Ada rule that scales with multi-asset data, dust folding, and the 16 k UTxO-set cap.

📐 The rules, in plain numbers

Every number on this page comes from these four constants — the same ones a node enforces when it validates.

💸 Linear fee

The minimum fee is proportional to transaction size. A 1-in/2-out send (~230 bytes) costs just 3,563 µAda.

minFee = 44 + 15.3 · bytes

⚖️ Minimum output

Every output must hold at least 1 Ada — plus 0.25 Ada per 34 bytes of token data. A multi-asset output with 8 tokens (100 bytes) must hold 4 Ada.

minOut = 1 + 0.25 · ⌈bytes/34⌉ Ada

🫧 Dust folding

If change is below the minimum, it can't be its own output. Wallets fold the dust into an existing plain output instead of losing it to fees.

change < minOut ⇒ fold

🪟 UTxO-set cap

Mainnet rejects transactions that would push the UTxO set past 16,384 entries — a hard cap that drives pruning and hygiene.

|UTxO set| ≤ 16 384

🧠 About this lab

Everything runs in your browser against the pure engine in coinselect.js, covered by unit tests (coinselect.test.mjs). Byte estimates use standard on-chain sizes (120 B/input, 55 B/plain output, 34 B per multi-asset unit, 1070 B Plutus budget), so the fee is an excellent approximation of what the network will charge. No wallet, no key, no network — nothing ever leaves this page.

Educational tool: real wallets may choose different inputs, and the network's exact byte count depends on the precise script/token payload. Verify amounts before signing anything.
